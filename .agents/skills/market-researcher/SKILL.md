# Market & Agile UX Researcher Skill — DevBoard

## Misión
Asegurar que ninguna decisión de producto, interacción o arquitectura de interfaz en **DevBoard** se tome a ciegas o desde la intuición vacía. Investigar cómo los referentes dorados del mercado de herramientas para desarrolladores (Linear, GitHub Projects, Jira, Height, Notion) resuelven problemas de organización ágil y ergonomía de flujos.

---

## 🔍 Ejes de Benchmarking para DevBoard

### 1. Ergonomía de Tableros Kanban y Columnas
- **Personalización de Columnas & WIP Limits (ref: Linear & Jira):** Cómo manejar columnas opcionales (columna "Ideas" o "Backlog" colapsada por defecto), límites de trabajo en progreso con advertencias visuales elegantes y reordenamiento intuitivo.
- **Transición de Estados:** Cómo guiar la promoción de tareas entre estados (`draft` -> `doing` -> `review` -> `ready` -> `done`) sin fricción ni clics superfluos.

### 2. Edición Rápida y Triage de Backlog
- **Layout de Modales de Tarea (ref: Linear & GitHub Issues):** Estructura de dos columnas (cuerpo principal para descripción y checklist de criterios; barra lateral o acordeón para metadatos como prioridad, sprint, etiquetas y asignados).
- **Acciones Masivas (Bulk Triage):** Selección de múltiples tarjetas para cambiar estado, hito o tags en un solo paso con barra de acciones flotante inferior.

### 3. Filtrado Dinámico y Búsqueda
- **Barra de Filtros y Atajos (ref: GitHub Projects & Notion):** Filtros visuales combinados (prioridad + hito + etiqueta + búsqueda libre), persistencia de vistas filtradas y botón de reset con contador de filtros activos.
- **Acceso por Teclado:** Integración fluida de búsqueda rápida con atajos estándar (`/` o `Cmd+K`).

### 4. Release Hub & Trazabilidad
- **Empaquetado de Versiones (ref: GitHub Releases & Git Tags):** Vinculación directa entre tareas completadas y changelogs automáticos listos para publicar en producción.

---

## 📋 Proceso de Trabajo
Al diseñar una nueva funcionalidad o rediseñar una vista en DevBoard:
1. **Identificar el Patrón Referente:** Contrastar cómo lo resuelven al menos 2 referentes (ej: Linear vs GitHub Projects).
2. **Resumir Buenas Prácticas:** Extraer los 3 principios clave de ergonomía para el Diseñador y el Ingeniero.
3. **Evitar Anti-Patrones Comunes:** Advertir sobre complejidades innecesarias (ej. excesiva configuración o menús sobrecargados).
